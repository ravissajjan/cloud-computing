# PART A: Enable MFA on Root Account

## STEP 1: Go to IAM
1. Search bar → Type `IAM` → Click **IAM**
2. Look at Security recommendations (you'll see a warning that MFA is not enabled)

## STEP 2: Enable MFA
1. Click **Add MFA** (in recommendations)
2. Device name: `root-mfa`
3. Select: **Authenticator app**
4. Click **Next**

## STEP 3: Set Up Phone
1. Open **Google Authenticator** on phone (or Microsoft Authenticator, Authy)
2. Tap **+** → **Scan QR code**
3. Scan the QR code on screen

💡 **Don't have an authenticator app?** Download Google Authenticator from App Store/Play Store first.

## STEP 4: Verify
1. Enter 6-digit code from app: `______`
2. Wait for code to change
3. Enter NEW code: `______`
4. Click **Add MFA**

✅ Root account protected!

# PART B: Create IAM User

## STEP 5: Create User
1. IAM → **Users** (left menu)
2. Click **Create user**

| Field | Enter |
|-------|-------|
| User name | `dev-yourname` |
| ✅ Check | Provide user access to AWS Console |
| Password | Autogenerated |
| ✅ Check | User must create new password |

Click **Next**

## STEP 6: Set Permissions
1. Select **Attach policies directly**
2. Search: `ReadOnlyAccess`
3. ✅ Check **ReadOnlyAccess**
4. Click **Next**

## STEP 7: Create
1. Click **Create user**
2. ⚠️ Click **Download .csv file** (save it!)

## STEP 8: Test New User
1. Open **incognito browser window**
2. Go to sign-in URL from CSV
3. Enter username & password
4. Create new password

## STEP 9: Verify Permissions
| Try This | Expected |
|----------|----------|
| EC2 → View instances | ✅ Works |
| EC2 → Launch instance | ❌ Not authorized |
| S3 → View buckets | ✅ Works |
| S3 → Create bucket | ❌ Access denied |

✅ Least privilege working!

# PART C: Security Groups

Go back to **root account** browser.

## STEP 10: Create Web Server SG
1. Search → **EC2**
2. Left menu → **Security Groups**
3. Click **Create security group**

| Field | Enter |
|-------|-------|
| Name | `lab2-web-sg` |
| Description | `Web server firewall` |
| VPC | Select **default VPC** |

**Add Inbound Rules:**
| Type | Port | Source |
|------|------|--------|
| HTTP | 80 | Anywhere (0.0.0.0/0) |
| HTTPS | 443 | Anywhere (0.0.0.0/0) |
| SSH | 22 | My IP |

Click **Create security group**

## STEP 11: Create Database SG
1. Click **Create security group**

| Field | Enter |
|-------|-------|
| Name | `lab2-database-sg` |
| Description | `Database firewall` |
| VPC | Select **default VPC** (same as web-sg) |

**Add Inbound Rule:**
| Type | Port | Source |
|------|------|--------|
| MySQL/Aurora | 3306 | Custom → select `lab2-web-sg` |

Click **Create security group**

💡 Database only accepts connections from web servers, not internet!

# PART D: S3 Encryption

## STEP 12: Create Encrypted Bucket
1. Search → **S3**
2. Click **Create bucket**

| Field | Enter |
|-------|-------|
| Bucket name | `secure-data-yourname-123456` |
| Region | US East (N. Virginia) |

💡 **Bucket names must be globally unique!** Replace `yourname` with your actual name and add random numbers until it works.

**Settings:**
| Setting | Value |
|---------|-------|
| Block all public access | ✅ Enabled |
| Bucket Versioning | Enable |

**Default Encryption:**
| Setting | Value |
|---------|-------|
| Encryption type | SSE-S3 |
| Bucket Key | Enable |

Click **Create bucket**

## STEP 13: Upload & Verify
1. Click your bucket
2. Click **Upload** → **Add files** → Select any file
3. Click **Upload**
4. Click the file → Check **Server-side encryption** = SSE-S3

✅ Data encrypted at rest!

# 🚀 PART E: Lambda Serverless

## STEP 14: Create Lambda Function
1. Search → **Lambda**
2. Click **Create function**

| Setting | Value |
|---------|-------|
| Choose | **Author from scratch** |
| Function name | `hello-cloud` |
| Runtime | **Python 3.12** |

3. Click **Create function**

## STEP 15: Write Your Code
1. Scroll down to **Code source**
2. Replace ALL the code with:

```python
import json
from datetime import datetime

def lambda_handler(event, context):
    current_time = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    
    return {
        'statusCode': 200,
        'body': json.dumps({
            'message': 'Hello from the Cloud! 🚀',
            'your_name': 'YOUR_NAME_HERE',
            'executed_at': current_time,
            'mind_blown': 'No server needed!'
        })
    }
```

3. Click **Deploy** (to save)

## STEP 16: Test It!
1. Click **Test** (orange button)
2. Event name: `test1`
3. Click **Save**, then **Test** again

✅ You should see green "Execution result: succeeded"

**Click "Details" to see your output!**

## STEP 17: Make It a Real API (Bonus!)
1. Go to **Configuration** tab → **Function URL**
2. Click **Create function URL**

| Setting | Value |
|---------|-------|
| Auth type | **NONE** (for demo only) |

⚠️ **Security Note:** Auth type NONE means anyone with the URL can call your function. Only use for demos/learning. In production, use **AWS_IAM** or add authentication in your code.

3. Click **Save**
4. 📋 **Copy the Function URL**
5. Open it in a new browser tab!

🎉 **You just created a live API endpoint!**

📱 **Share with classmates!** Send them your Function URL - they can call YOUR API from their browser!

# PART F: Security Monitoring

## STEP 18: View CloudTrail Events
1. Search → **CloudTrail**
2. Click **Event history** (left menu)
3. You'll see recent API calls in your account

| Column | What It Shows |
|--------|---------------|
| Event name | What action was performed (CreateUser, RunInstances) |
| User name | Who did it |
| Event time | When it happened |
| AWS access key | Which credentials were used |

4. Click any event → See full JSON details

💡 **This is your audit trail!** If someone deletes a resource, CloudTrail shows who and when.

## STEP 19: Enable GuardDuty
1. Search → **GuardDuty**
2. Click **Get Started**
3. Click **Enable GuardDuty**

✅ GuardDuty now monitors for threats!

**What GuardDuty detects:**
| Finding Type | Example |
|--------------|----------|
| UnauthorizedAccess | Someone using stolen credentials |
| CryptoCurrency | EC2 mining bitcoin |
| Recon | Port scanning your instances |

💡 **Free 30-day trial** - disable after workshop to avoid charges.

## STEP 20: View VPC Configuration
1. Search → **VPC**
2. Click **Your VPCs** → Note the default VPC
3. Click **Subnets** → See availability zones
4. Click **Internet gateways** → Enables internet access
5. Click **Route tables** → Shows traffic routing rules

💡 **Understanding:** Your EC2 instances live inside VPC → Subnet → with Security Groups as firewalls. This is why you selected the default VPC when creating security groups!

## CLEANUP

⚠️ **Delete in this order** (dependencies matter!):

💡 **Keep MFA enabled on root!** This is a security best practice - don't remove it.

| Step | Resource | How to Delete |
|------|----------|---------------|
| 1 | GuardDuty | GuardDuty → Settings → **Suspend GuardDuty** → **Disable** |
| 2 | Lambda Function URL | Lambda → Function → Configuration → Function URL → **Delete** |
| 3 | Lambda Function | Lambda → Functions → Select → Actions → **Delete** |
| 4 | S3 Bucket | S3 → Select → **Empty** → **Delete** |
| 5 | IAM User | IAM → Users → Select → **Delete** |
| 6 | Database SG | EC2 → Security Groups → Select `lab2-database-sg` → **Delete** |
| 7 | Web SG | EC2 → Security Groups → Select `lab2-web-sg` → **Delete** |

💡 **Note:** Delete `lab2-database-sg` first because it references `lab2-web-sg`. You cannot delete a security group that is referenced by another.

## Troubleshooting
| Problem | Fix |
|---------|-----|
| MFA code rejected | Check phone time is auto-synced |
| Can't scan QR | Click "Show secret key", enter manually |
| IAM login fails | Use sign-in URL from CSV (not regular AWS login) |
| Bucket name taken | Add more random numbers (e.g., `yourname-987654`) |
| Lambda test fails | Check syntax, click **Deploy** before Test |
| Function URL 403 | Check Auth type is NONE |
| Function URL shows raw JSON | That's correct! It's an API response |
| GuardDuty not available | Check region supports GuardDuty |
| CloudTrail empty | Events take ~15 min to appear |
| Security group delete fails | Delete database-sg before web-sg |
| "You need permissions" error | Switch back to root account browser |

**Stuck? Raise your hand!** 🙋
